# 订单状态流转需求

## 1. 功能描述

订单在生命周期内按既定状态机流转，各状态转换受业务规则约束。

## 2. 状态定义

订单状态集合：`待支付` / `已支付` / `已发货` / `已完成` / `已取消` / `售后中` / `已退款`

流转路径：

```
待支付 → 已支付（用户支付成功）
待支付 → 已取消（用户取消 或 超时自动取消）
已支付 → 已发货（商家发货）
已发货 → 已完成（用户确认收货 或 10 天自动确认）
已支付 → 售后中（用户对已支付订单发起售后）
售后中 → 已退款（售后审核通过）
售后中 → 已完成（售后驳回，订单回归原状态）
```

## 3. 流转约束规则

### 3.1 超时自动取消
- 规则名：`auto_cancel_timeout`
- 期望：待支付订单超过 30 分钟未支付自动取消

### 3.2 发货前置状态
- 规则名：`ship_requires_paid`
- 期望：仅「已支付」状态的订单可以发货

### 3.3 取消前置状态
- 规则名：`cancel_requires_pending`
- 期望：仅「待支付」状态的订单可以被用户取消

### 3.4 支付前置状态
- 规则名：`pay_requires_pending`
- 期望：仅「待支付」状态的订单允许支付，已取消或已退款订单不可再支付

### 3.5 售后发起条件
- 规则名：`aftersale_requires_paid`
- 期望：已支付且未进入售后的订单可发起售后申请

## 4. 状态变更提示文案

- 超时自动取消：「订单已超时自动取消」
- 未支付订单发货：「未支付订单不可发货」
- 非待支付订单取消：「仅待支付订单可以取消」
- 已取消订单支付：「订单状态不允许支付」
- 售后申请提交成功：「售后申请已提交，请等待审核」
- 状态变更推送：「订单状态已变更，请刷新查看」

## 5. 验收标准

1. 状态机中每条合法流转路径至少有一条验证用例
2. 所有非法流转（跳过中间状态、终态再操作）必须被拒绝并给出对应提示
3. 每次状态变更必须触发消息推送
