# /code-quality

审查代码质量，确保注释与代码比例不低于 3:7，每个函数/代码块有清晰注释。

## 用法
```
/code-quality                      → 审查全部代码
/code-quality core/                → 审查指定目录
/code-quality core/generator.py    → 审查指定文件
/code-quality --fix                → 审查后自动补充缺失注释
/code-quality --summary            → 只输出统计数据，不逐文件报告
```

## 审查规则

### 1. 注释覆盖率（核心指标）
- **目标**：注释行 : 代码行 ≥ 3 : 7（即注释不少于代码的 30%）
- 注释包括：块注释 `#`、多行字符串 `"""docstring"""`、行内注释
- 代码行不含空行和纯注释行
- 计算方式：`ratio = 注释行 / (代码行 + 注释行)`

### 2. 函数注释要求
每个函数/方法必须包含：
- **docstring**（`""" """`）：说明函数用途、参数、返回值
- **关键逻辑注释**：复杂算法、业务规则、边界处理处应有行内注释
- **TODO/FIXME**：标记已知待改进点

### 3. 代码块注释
- 每个逻辑段落（条件分支、循环、异常处理）上方应有注释说明意图
- 正则表达式、复杂推导式、魔法数字必须有注释
- 空 `except`、`pass` 必须有理由注释

## 输出格式
```
📋 代码质量报告: xxx.py

📊 统计
  - 总行数: xxx
  - 代码行: xxx | 注释行: xxx | 空行: xxx
  - 注释占比: xx% （目标 ≥ 30%）
  - 状态: ✅ 通过 / ❌ 未达标

🔍 问题清单
  1. [函数] xxx() — 缺少 docstring
  2. [代码] 第 xx 行 — 魔法数字 86400 无注释
  3. ...

💡 改进建议
  - xxx 行添加注释说明业务规则
```

## 约束
- 不修改逻辑代码，只补充注释
- 注释要说明**意图**（why），不要废话（what）
- 中文注释为主，专业术语可用英文
